# Check-in · «Паспорт VIVO»

PWA для сотрудников промо-зон в торговых центрах: отметка прихода и ухода с селфи и фото стенда. Руководитель смотрит отметки, фото и часы в Google-таблице.

Сайт: https://alexsonwe-bit.github.io/checkin/ — приложение в работе, им пользуются сотрудники. Любое изменение сразу влияет на живых людей.

## Как работать с владельцем

- Общаться по-русски.
- Инструкции давать по одному шагу: дождаться «готово», потом следующий шаг.
- После публикации на GitHub самому проверить, что Pages реально отдаёт новые файлы (содержимое репозитория и отдаваемый сайт проверять отдельно).
- Не утверждать то, что не проверено. Если что-то не подтверждено — так и сказать.
- Ничего необратимого (удаление файлов, старых версий фото на Диске) без явного подтверждения.

## Важно: репозиторий публичный

Репозиторий и корень Pages открыты всем. Не коммитить сюда: общий код проекта, ID таблицы и папок Диска, пароли, `Code.gs`, личные данные сотрудников. Этот файл тоже публичный.

## Состав

В репозитории (= опубликованный корень Pages, ветка `main`, корень `/`):

- `index.html` — весь интерфейс, стили и клиентская логика.
- `sw.js` — сервис-воркер, network-first, офлайн-кэш. Текущая версия кэша — `checkin-v5`.
- `manifest.webmanifest`, `icon-180.png`, `icon-192.png`, `icon-512.png`.

Вне репозитория (только у владельца локально, в публичный сайт не загружать):

- `Code.gs` — сервер на Google Apps Script. Живёт отдельно от GitHub: текущую развёрнутую версию проверять в редакторе Apps Script, а не по памяти.
- `README.md` с инструкцией по развёртыванию, тесты `test-multi.cjs` (несколько фото и ссылок в таблице) и `test-review-layout.cjs` (видимость кнопки «Отправить» на разных экранах).
- Папки `presentation`, `telegram`, `backups`, `checkin-retouch`.

Перед изменениями читать актуальные `index.html`, `sw.js` и (если менять сервер) свежий `Code.gs` от владельца — история в ChatGPT содержала несколько последовательных версий.

## Деплой

Клиент:
1. Изменить `index.html` и, как правило, `sw.js`; при любом изменении клиента повысить версию `CACHE` в `sw.js` (`checkin-v5` → `checkin-v6`).
2. Владелец обычно загружает файлы вручную: Add file → Upload files → Commit changes. Можно пушить напрямую, если он попросит.
3. Подождать публикацию Pages и проверить отдаваемые файлы.
4. Телефону иногда нужно дважды закрыть и открыть приложение с интернетом, чтобы подхватить новую версию.

Сервер:
- При изменениях API сначала обновить Apps Script, потом клиент.
- Обновлять существующее развёртывание, чтобы сохранить адрес `/exec`: «Управление развертываниями» → карандаш → «Новая версия» → «Развернуть». Запуск от имени владельца, доступ «Все».
- Адрес `/exec` прописан в `index.html`.

## Данные и сервер

Google-таблица (настройки и журнал):
- «Настройки» — название проекта, общий код, часовой пояс (обычно `Europe/Moscow`), разрешение свободного ввода точки.
- «Точки» — ТЦ, адрес, широта, долгота, радиус. Читаются сверху до первой пустой строки. Координаты можно вставить одной строкой в «Широту», оставив «Долготу» пустой.
- «Журнал» — каждая отметка: дата, время, тип, сотрудник, точка, селфи, стенд, карта, точность, расстояние до точки, получение сервером, замечания, ID. В ячейке «Стенд» несколько ссылок («стенд 1», «стенд 2»…).
- «Табель» — строка на сотрудника за день: первый приход, последний уход, длительность, фото, замечания. Повторные отметки остаются в журнале и помечаются.

Фото на Google Диске в подпапках `yyyy-MM-dd`; имя файла содержит время, ФИО, приход/уход, тип снимка и ТЦ.

Apps Script:
- `setup()` однократно создаёт структуру Диска и таблицу; ID хранятся в ScriptProperties.
- `doGet` — конфигурация и серверное время. `doPost` — проверка общего кода, сохранение фото, обновление журнала и табеля.
- POST идёт как `text/plain`, чтобы не было CORS-preflight.
- Payload поддерживает старое поле `photo2` и новый массив `standPhotos`. Новые колонки добавлялись автоматической миграцией.
- `LockService`; дедупликация по ID через CacheService ~6 часов (не постоянная гарантия).
- Ссылки в таблице — `RichTextValue` + `setLinkUrl`. Формулы `HYPERLINK` (через `appendRow` и `setFormula`) в русской таблице давали ERROR — не возвращаться к ним. `repairLinks()` чинит старые ссылки.
- Замечания сервера: расхождение времени > 2 минут; задержка получения > 10 минут.

## Клиент

- Поток: выбор ТЦ → фронтальная камера (селфи) → основная камера (стенд). Селфи: лицо, чистая форма, промо-зона. Стенд: 1–5 фото, каждый смартфон должен быть различим.
- Экран проверки: добавить, переснять или удалить доп. фото стенда. Фото в отдельном прокручиваемом блоке, кнопка «Отправить» закреплена снизу — так исправлена пропадавшая кнопка в вертикальной ориентации. Не возвращать горизонтальную общую панель.
- Запасной вариант при проблемах с камерой — системная камера через `<input type=file capture>`; на разных телефонах ведёт себя по-разному.
- Водяного знака / штампа на фото нет (убран по просьбе владельца в v5). Время, координаты и ФИО передаются только как данные отметки.
- `localStorage`, ключ `checkin.v1`: профиль, настройки, поправка времени, история. Хранится 20 последних отметок, на главном показывается 8; верхние блоки прихода/ухода — только за текущий день.
- Время: клиент получает `serverTime`, считает `S.offset`; время снимка = `Date.now() + S.offset`. Сервер отдельно пишет момент получения.
- Офлайн: отметка с фото сначала пишется в IndexedDB (база `checkin`, хранилище `queue`), затем отправляется; при восстановлении связи — повтор. Фоновой доставки после закрытия приложения нет. Без IndexedDB — прямая отправка с обработкой ошибки.
- ФИО вводит сотрудник сам, авторизации и базы сотрудников нет; вход по общему коду проекта. Смена кода = сообщить новый всем сотрудникам.

## Дизайн

- Русский интерфейс, простые действия, крупные кнопки.
- Синий — основной цвет, зелёный — приход, оранжевый — уход. Тёмная тема и безопасные области iPhone.
- Основное действие на экране проверки всегда видно снизу.
- В примерах писать ТЦ и адрес, без названий торговых сетей (DNS, М.Видео и т.п.).

## Известные ограничения и открытые задачи

- Час расхождения между часами iPhone и временем отметки (ноябрь 2026) — причина не установлена. Гипотеза для проверки: устаревшая `S.offset` после смены системного времени, если новая синхронизация не прошла из-за долгого ответа.
- Проверить фактические права доступа к таблице, папкам и фото на Диске — владелец хочет единолично контролировать журнал и фото, а интерфейс Диска показывал «В общем доступе».
- Запись фото и строки в таблицу не транзакционна: при частичном сбое возможны лишние файлы и дубли. Дедупликация (проверка кэша до блокировки, ограниченный срок) не гарантирует уникальность.
- Одинаковые ФИО сливаются в табеле — уникальных ID сотрудников нет.
- Ночная смена через полночь не поддерживается группировкой по дню.
- Полной защиты от подмены фото и координат нет.
- PDF-инструкция для сотрудников устарела: описывает два фиксированных фото и водяной знак/защиту от подделки. Обновить под 1–5 фото стенда и отсутствие штампа.
- Старые версии отретушированных архивных фото (15–16.11.2026) хранятся в истории файлов Диска; удалять только после явного подтверждения.

## Решения и почему

- PWA — одинаковая установка на Android и iPhone без магазинов приложений; нативные приложения не заказывались.
- GitHub Pages — знакомая владельцу площадка, простой ручной деплой.
- Google Диск + Apps Script — выбор владельца: удобный просмотр фото и табеля, минимум настройки. Yandex Cloud рассматривался как запасной (нужна карта и сложнее инфраструктура).
- Общий код проекта — простой вход без учёток.
